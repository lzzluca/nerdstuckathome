# Luca's writing style

Derived from his posts on nerdstuckathome.wordpress.com from 2012 to 2022, read in full: the two Intigriti challenge write-ups (2022), "Lint only touched files with Webpack" (2016), "Be careful with your fix!" (2014).

Write in this voice, with fully correct English. Copy the voice, never the grammar mistakes of the originals.

## Voice

- First person, like a dev log shared with a friend, not a tutorial. "We" when walking the reader through the reasoning ("we need it to return true", "let's start from there").
- Enthusiastic and modest. Pride is said openly and with a smile ("sharing it just because I'm proud of it <3").
- Honest about uncertainty: "I'm not 100% sure why (!), my guess: …", "to be honest, at this point I wasn't sure how to proceed", "that part confused me the most".
- Light humor from talking to himself: "easier said than done". Strong reactions belong to the post that earns them, so never as a recurring tic.
- Everyday anchors for abstract points: "Little example: yesterday I was sending an email with Gmail…".

## Structure

- Open with personal context in one or two plain sentences: "Recently I had to…", "For a while now, … has been one of my favourite…". No hook, no thesis.
- In a write-up, give the result first ("I'm going to give away the solution first, which looks like this:"), then how he got there.
- Long posts get a short table of contents and plain sentence-case headings that name the stage: "Investigating the problem", "Working on the solution".
- Tell it chronologically: first attempt, why it failed, the next one, the one that worked. Dead ends stay in. Inline labels mark the turns: "Problem:", "Follow-up problem:", "Final bit:", "That's it!".
- Numbered observations early on, referenced later ("see point 3 above", "if you remember, point 4 said…").
- Digressions are announced and closed: "Before the last step, a digression…", "Digression closed, I hope it was worth it".
- Shows unfinished work honestly: "I'm pasting it as it is now", TODOs left in, "it still needs work, but it does the job, so it's worth sharing".
- End with the takeaway in a line, a small tip if there is one ("suggestion: allow lists over block lists!"), then "Thanks for reading!". A PS is a last resort for one line that found no place in the body; it reads like a digression, so fit the line in earlier when possible.

## Sentences

- Colons chain cause and effect a lot: "Problem: Mithril has a virtual node for main, which overrides our HTML."
- Mix medium sentences joined with "so", "but", "because", "in fact", "anyway", with short ones after a setback or a win.
- Parentheses for asides and self-deprecation: "(probably obvious and not needed!)", "(maybe!)", "(for one char only)".
- Exclamation marks for real reactions and the sign-off. Ellipses (…) now and then for a trailing thought.
- Code comments can carry the same voice in first person: `// I add an attachment!`, `// I run on the send button click`.

## Not his style

- Polished essay voice, aphorisms, dramatic one-line paragraphs, "not X but Y" contrasts.
- Bold statements of authority. He hedges with "I think", "I believe", "probably", and means it.
- Em dashes as connectors. He uses colons, commas and parentheses.
